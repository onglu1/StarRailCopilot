# 差分宇宙无人值守上线验收

2026-10-13 用户确认的新目标：优先确保卡住后恢复运行，允许放弃问题局并正常结算重开。旧版“每关非战斗都低于 60 秒、任意故障 100% 自愈”不再作为上线门槛。

## 必须满足的条件

1. 首次故障重启恢复原局；同关再次失败转为正常结算，再按用户 Runs 设置开下一局。次数和等待时间有界。
2. 冻结同一版本，两台各连续 5 局，至少 9 局真实通关，不允许中途人工游戏操作、修改代码或重载。冒险退出、战败、未确认结果、终止错误都计未通关。不能挑选较好的窗口重算。
3. “重启继续原局”及“问题局真实结算并自动开下一局”分别实机验证。受控故障明确标识，单独作为恢复专项，不混入自然运行成功率。
4. 所有验收关卡非战斗耗时 P50 ≤60 秒、P90 ≤120 秒。扣除已记录的原生战斗，保留移动、识别、领奖、过门、恢复及加载。缺失计时不能冒充通过。
5. 外部不可用、登录验证或真实结算无法确认时，有界停止并保留现场/原局/历史；用户主动停止不得自动拉起。

## 当前恢复实现

- `state/divergent_universe/<profile>.json` 的 `recovery` 保存 run ID、节点、故障次数、重启次数、恢复阶段和截止时间。改变战斗数或站点名称不会清空同关预算。
- 首次失败进入 `resume`，同关第二次任务故障进入 `settle`，持久化 `stop_requested` 和 `exit_reason=recovery_same_node`。
- `RecoveryRetries` 是整个同关恢复的重启总上限（当前两配置均为 3）；0 表示不自动恢复。若用户设置过小，可能在无法进入第二阶段前耗尽预算，不擅自扩大其设置。
- 每个恢复阶段最多 600 秒，并受原生登录 300 秒、退出菜单/转场自身超时和用户停止检查约束。第二阶段的重试和 worker 重载均不能续期。真正进入下一节点才清除原局恢复预算；已有结算请求则必须保留到真实结束。
- 恢复耗尽保留现场并抛出原生接管异常，不伪造胜利或清空原局。入口显示新局但缺少所请求的结算证据时同样停止。
- `Progress.finish` 仍强制 `settlement_observed=true`，问题局结果为 `interrupted`。

## 受控实机验证

生产默认关闭故障注入。仅本地验证 GUI 进程显式设置 `DU_RECOVERY_PROBE` 为本包 `state/divergent_universe/validation` 目录时启用。每个配置独立 JSON 请求，必须同时匹配配置、原局 ID、当前节点和有效期，剩余次数只允许 1 或 2；每次在抛出验证异常前原子消耗次数。请求用尽不再触发。

注入位置是生产脚本刚确认的世界页/当前节点，不发送模拟器操作。重启、暂离、结算和开下一局全部走正常生产路径。事件日志写 `recovery_probe_injected`，用于区分测试故障和自然故障。专项完成后关闭注入进程环境再启动正式冻结验收；版本代码保持一致。

### 恢复与失败边界

- 同一运行代码的受控实机专项：配置A首次故障后保留原局并跨关；配置B同关第二次故障后实际结束并结算为 `interrupted`，自动启动新局并实际进入第1关。注入只负责抛出测试异常，所有游戏动作由生产流程执行，专项不计入上述10局。
- 固定10局中另有3次自然故障：配置A第3局精英7、配置B第5局事件5和异常11；分别在故障后241.824、165.657、177.097秒实际跨关，全部保留原run并最终win。两次配置B故障发生在不同节点，只有实际跨关才清除上一节点恢复预算。
- 登录失败、结算无法确认、用户停止、重载后预算/截止时间保留等9项局部控制与实际checkpoint文件测试通过。原生登录及战斗回调均检查停止请求/截止时间；耗尽时由原生接管异常结束worker并留证。未在实机上人为断网或破坏模拟器，不把局部模拟当实机断网测试。
- 当前两配置保留周期演算/full/Runs0、UseTechnique=false、RecoveryRetries3及全部原有难度/队伍/图鉴设置。冒险全部避免，误入时真实结算计interrupted；本次自然10局未发生冒险退出。
